# FMoT Rail Project Tracker

Project tracker for Nigeria's Federal Ministry of Transportation to track railway construction projects. Built by Schull Technologies.

Read `docs/screen-map.md` before any design or UI work and `docs/process-model.md` before any data-model, workflow or permissions work.

## Design work in Penpot

- Penpot 2.18, self-hosted at http://localhost:9001, reached through the `penpot` MCP server. The browser tab with the file must stay open with the MCP toggle on.
- Team "Schulltech Team", project "FMoT Rail Project Tracker".
- File "Wireframes" is the low-fidelity spec; read a wireframe board before building its hi-fi version, and never change it from the hi-fi work.
- File "FMoT Rail Tracker: Design System" is the shared library: pages 00 Cover, 01 Tokens, 02 Foundations, 03 Icons, 04 Atoms, 05 Molecules, 06 Organisms, 07 Templates, 99 Scratch. Leftovers go to 99 Scratch; nothing is deleted.
- File "FMoT Rail Tracker: UI" holds the hi-fi screens and consumes the library. Its pages and board names mirror Wireframes (screens/<id>, 1440x1024 web, 390x844 phone, 100 px gutters). Never mix library work and screen work in one file.
- The MCP plugin works only in the file it is open in; it cannot create files, switch files or publish a library. Those steps are done by hand in the Penpot dashboard.
- Pages are numbered so they sort: `01 Web Map home`, `02 Web Project view`, `03 Web Create project`, `04 Web Tasks`, `05 Setup`, `06 Mobile`.
- One board per screen, named `screens/<id>` using the ids in the screen map (`screens/w3-map-home`, `screens/m2-home`). Desktop boards are 1440x1024, phone boards 390x844, with 100 px gutters between boards.
- Layers are named `section/element`, lowercase, no spaces around the slash.
- Wireframes are low fidelity: greys, one dark accent for primary buttons, native Penpot text layers. The first two boards (`w3-map-home`, `w5-project-view`) carry raw-SVG text that will be replaced later; leave them.
- Never delete shapes, boards or pages. Read a board back after building it and fix overlaps.

## Design system rules

- Tokens are dot paths, lowercase, kebab-case words, in five sets: `core` (what it is: `color.navy.900`, `spacing.16`), `semantic` (what it is for: `color.text.secondary`, `color.status.stalled.line`, `type.body`), `component` (where it is used: `button.primary.bg`, `map.corridor.width`), and two override sets, `semantic-large-text` (font-size.* +25 percent) and `semantic-high-contrast` (darker text, borders and lines). The full catalogue is in `tools/penpot-ds-tokens.json`.
- Themes, group Mode: Light (default: core, semantic, component), Large text (adds semantic-large-text), High contrast (adds semantic-high-contrast).
- Token changes go to both files. Penpot does not share tokens through a connected library, so the Design System file and the UI file each hold their own copy of the catalogue. Change a token in the Design System file first, make the same change in the UI file, then update `tools/penpot-ds-tokens.json`. On 29 October 2026 both files held the same 265 tokens with the same values and themes.
- Themes are file-wide, and layout only reflows on the page that is open. After switching theme, open each page in turn; after a check, switch back to Light the same way. A spacing or size set by hand on a token-bound property is reset by any theme switch, so bind a token instead.
- Screens and components use semantic or component tokens only, never core tokens, and never a raw value on a shape. Library colours (`core/<family>/<step>`, `semantic/<group>/<name>`) and typographies (`type/<name>`, `type/phone/<name>`) are generated from the tokens and store their source token; regenerate them with `D.genColors()` and `D.genTypos()`.
- Status families are fixed: operational (green; also commissioned), under-construction (orange), planned (grey; identified, funded, contracted), stalled (red), draft (dashed grey). Each has `.line` for map and legend, `.fg` and `.bg` for chips. The gate strip uses the same families: passed green, current orange outline, blocked red, not started grey outline.
- Navy is the primary action colour. Nigeria green only appears in the header stripe and crest area, never on a button or as a status. The crest slot (40x40) holds the coat of arms of Nigeria in the web and mobile apps (since 3 November 2026; source, CC BY-SA 3.0 credit and the files made from it in `docs/brand/README.md`); the Penpot boards still show the placeholder.
- Type: Outfit (since 29 October 2026; it replaced Inter), fallback Source Sans Pro. Every typography token points at `font.family.ui`, so a font change is that one token in both files plus `D.genTypos()` or `setFont` on the library typographies in the Design System file.
- Accessibility: body 16 px web and 18 px phone, nothing below 13 px, body line height 1.5, 4.5:1 for text and 3:1 for UI parts in every theme, 48 px touch targets on phone, one primary action per screen, shadows no deeper than 2 px.
- Components are named `atoms/<name>`, `molecules/<name>`, `organisms/<name>`, `templates/<name>` and `icon/<name>`, all lowercase, with states and sizes as Penpot variants.

## Known limitations

- Variant switching on nested instances does not work through the plugin API (`switchVariant` fails on nested and older instances), so a few nested states (toggle positions, the draft header chip) are visual overrides, not true variants. Swap them by hand in Penpot if the variant matters.
- Some what-is-this tile kinds use generic Lucide icons as stand-ins (Equipment is a wrench; others reuse existing icons). Replace them when proper icons exist.
- Penpot themes are file-wide: Light, Large text and High contrast cannot sit side by side in one view, so the Large text proof boards only show Large text while that theme is active. Layout only reflows on the page that is open, so after a theme switch, open every page in turn.
- Penpot only re-measures text that is in the viewport. After a font, theme or text change, zoom to fit the page (or zoom into the shape) before reading sizes, exporting or running QA; boards elsewhere keep stale sizes until then.
- Instances whose text was overridden keep their own geometry, so a layout fix in a library component does not reach them through a library update. Re-apply the fix to the instances (`uiLargeTextFixes` in `tools/penpot-helpers.js`) or rebuild them from fresh instances.
- The plugin API cannot remove a token from a shape. `molecules/table-row` body rows still carry the `table.row-height` token on height although they now hug their content; a theme switch leaves them on auto, but unbind it by hand if it ever forces 48 px back.

The page 07 code (layout, wiring table, QA and the Large text fixes) is `installUI3` in `tools/penpot-helpers.js`.

## The API

The API (NestJS on Neon PostgreSQL with PostGIS: database, sign-in, projects, field uploads, approvals, payments, progress, notifications, reports) is in the private repository `SchullGroup/FMOT-Project-Tracker-API`, with its own CLAUDE.md. Clone it beside this folder (`../fmot-rail-tracker-api`) and run it from there (`pnpm dev`, port 4000); the web app's `/api` proxy and the field app reach it there.

`packages/shared` here (`@fmot/shared`: roles, permissions, workflow definitions, the OpenAPI document and its types) is a copy of the API repository's, where `pnpm api:types` regenerates the types. After it changes there, run `pnpm shared:sync` (`tools/sync-shared.sh`, which copies it from `../fmot-rail-tracker-api` or the path given) and commit the result, so the web and field apps build against the same roles, permissions and API types.

## Web app

Code in `apps/web`: Next.js 16 (App Router, TypeScript strict), Tailwind CSS 4, MapLibre GL 6, TanStack Query 5, Outfit from npm. `apps/web/README.md` and `HANDOVER.md` describe the screens; screen ids follow `docs/screen-map.md`.

- Run: `pnpm dev` starts the API and the web app together (`pnpm web` for the web app alone, on :3000). The browser talks only to the web app's origin: `/api/*` is forwarded to `API_ORIGIN` (default `http://localhost:4000`, `next.config.ts`), so the refresh cookie is first-party and there is no CORS. The access token lives in memory (`src/lib/api.ts`); a 401 refreshes once from the cookie and retries.
- Sample data: `NEXT_PUBLIC_API_MOCK=1 pnpm web` runs every screen on built-in data (`src/lib/mock*.ts`, written in the screen shapes): the test numbers of docs/demo-data.md (`src/lib/demo-accounts.ts`, listed under "Test accounts" on the sign-in page in sample mode only), each signing in as that person with their role's permissions from `@fmot/shared`, the code 000000 and the PIN 4826 (also for PIN confirmations); other numbers get "not one of the test numbers"; the walkthroughs use the unlisted 0700 000 0199, which sees every area; Kaduna–Kano (`/projects/p-kk`) has every section filled.
- The contract: every API call is in `src/lib/endpoints.ts`, which maps the API's responses (`src/lib/api-shapes.ts`) onto the shapes the screens use (`src/lib/types.ts`) and the screens' requests onto the API's fields (funding route `loan` is `external_loan`, origin `presidential_directive` is `directive`, `returnReasonId` is the return reason code, gate 1's date travels with Send for publishing, kobo arrives as a string of digits, money settings are shown in naira). In sample-data mode nothing is mapped. When the API changes a response, change `api-shapes.ts` and the mapping, not the components.
- Roles, role labels, organisation rules and permissions come from `@fmot/shared` (`src/lib/roles.ts`, `src/lib/org-roles.ts`, `useCan(permission)`); errors carry a stable `code` (`apps/api/src/common/errors.ts`) with plain messages in `src/lib/messages.ts`.
- Files: documents and reports open through signed links (`GET /api/documents/:id/download`, `GET /api/reports/:id/file` return `{ url }`, valid 5 minutes, no access token needed).
- Design tokens: the `@theme` block in `src/app/globals.css` is generated from `tools/penpot-ds-tokens.json` by `pnpm tokens` (`tools/tokens-to-css.mjs`); change the tokens, not the block. Status colours only through `src/lib/status.ts` and `--color-status-*`.
- Maps: one style URL and the CC BY 4.0 boundary credit in `src/lib/map.ts` for all three maps (map home, corridor, wizard preview). `NEXT_PUBLIC_MAP_STYLE_URL` takes any MapLibre style (README: MapTiler satellite-hybrid); `public/map-style-plain.json` is the offline style the tests use.
- Security: `src/proxy.ts` sets the Content Security Policy with a nonce per request (scripts and styles only from the app with the nonce; images, connections and workers from the app and the map style's origin, plus `MAP_EXTRA_ORIGINS`; no frames or objects). The root layout reads the nonce, so every page is rendered per request. `next dev` gets `'unsafe-inline'` styles and `'unsafe-eval'`, which it needs. `next.config.ts` adds HSTS, nosniff, frame denial, referrer and permissions policies, and builds a standalone server for the Docker image. `API_ORIGIN` and `NEXT_PUBLIC_*` are fixed at build time.
- Web Step 7 forms (`src/components/forms/`): what each lot needs approved (Design, `progress:plan`), the programme and its revisions with a blank CSV template made in the page (Progress, `progress:plan`), practical completion with the PIN (Progress, `completion:record`), and bonds, guarantees, insurances and EIA conditions (Documents, `obligations:manage`; the API has no owner field, so who is reminded follows from the kind). Sample data in `src/lib/mock-forms.ts`.
- Web Step 8 actions (`src/components/forms/`): New valuation on Payments (`valuations:submit`, the lot's contractor commercial manager; it shows the RE's measurement for the month from `GET /api/lots/:id/valuations/prefill?periodMonth=` and sends it as the valuation's quantities), Add a lot on Corridor (`lots:manage`; contractors and consultants from `GET /api/organisations?type=`; the Director confirms the lot), Add a member on People (`members:manage`; people from outside the ministry wait for the Director), Send a design package on Design (`design:submit`). A draft project shows a "Not published" banner on every section and only its gates on the overview. Sample data in `src/lib/mock-step8.ts`.
- Web Step 9 brought the screens closer to the Penpot boards: map filter chips (Status, Phase, Funding, Contractor, State) with a Drafts chip, a plain legend and a Layers panel remembered on the device; task screens in two columns with "Why you" and a sentence saying what the button does (`src/lib/task-copy.ts`, keyed by the API's task types grouped by chain); the PIN as a keypad sheet (`src/components/PinPad.tsx`; four digits send it, and digits typed anywhere in the sheet count); payments as a certificate table with "Contract to date"; the overview with alerts, figures beside the gates and a small corridor map; the draft overview with "What publishing does". Deliberately not taken from the design: the notification bell (no feed in the API) and wording where the app's is plainer.
- Items from site (W5.4 and W7.4): every card on Photos and reports opens `/projects/:id/photos/:itemId`, the photos large (both for a milestone claim), the voice note, a report's answers, where and when, and the automatic checks in plain words (`CheckList`, grey for `not_available`). The lot's resident engineer (`canReview` from `GET /api/field/submissions/:id`, which also gives who sent it, the lot, the milestone and who reviewed it) verifies it or sends it back with a reason from the list (`ReturnSheet`), then goes to the next item waiting; everyone else reads it. The Review queue task links to the same list.
- The API client refreshes the session only on a 401 whose code is `unauthorized` (or a bare 401). Other 401s (`pin_incorrect`, `code_incorrect`) are shown as they are; retrying them after a refresh would count a wrong PIN twice towards the lock.
- Money: anything someone claims, approves or pays is shown to the kobo with `formatNairaExact` and typed amounts are turned into kobo with `nairaToKobo`, both in bigint so nothing rounds; `formatNaira` (compact) is for overviews only.
- Request bodies sent to the API are checked at compile time against its DTOs: `satisfies ApiBody<'CreateProjectDto'>` in `endpoints.ts`, with types from `@fmot/shared`.
- Tests: `pnpm --filter web test` runs the nine walkthroughs (the six in HANDOVER.md, Web Step 7's forms, Web Step 8's actions and Web Step 9's design changes) with Playwright on sample data (no API, no database, no tile server; `next dev` on :3100), and fails on any Content Security Policy violation. `pnpm --filter web test:real` runs the walkthrough against the real API (e2e-real/, see its header): invites, the wizard with a real KML, publishing with the PIN, every project section, a contractor account confirmed by the Director. It leaves its people and project on the branch it runs against.

## Field app (mobile)

Code in `apps/mobile` (README there: how to run it on a phone, the API address, what does not work in Expo Go). Expo SDK 58 (React Native 0.88, React 19.3.0), TypeScript strict, Expo Router (`src/app/`, protected routes by state: first run, signed out, locked, open), run in Expo Go on Android and iPhone; in-house only, nothing published.

- Only modules that are in Expo Go: expo-camera, expo-location, expo-sqlite (settings in its kv-store, and the outbox), expo-audio, expo-secure-store, expo-local-authentication, expo-file-system, expo-image-manipulator, expo-network, expo-localization, expo-font (Outfit from `@expo-google-fonts/outfit`), lucide-react-native with react-native-svg for the boards' icons. No custom native code. Install with `pnpm --filter mobile exec expo install <pkg>` so versions match the SDK.
- pnpm's isolated installs work with SDK 58 (Expo's monorepo guide); no `nodeLinker: hoisted`, no `.npmrc`, no Metro config. `@fmot/shared` (roles, permissions) is a workspace dependency, used built.
- Who: contractor site managers (M2 home) and consultant resident engineers (M9). Anyone else gets "This app is for site staff" and signs out.
- Sign-in (`src/lib/api.ts`): `X-Client: mobile`; the refresh token comes in the body and lives only in expo-secure-store, the access token only in memory; a device id made on first run and kept in secure storage binds the phone; phone number or email address, the code (by SMS or email, to what was typed), then PIN (entered, or set twice); invites by the 8-character code from the invite text message or email, then the code by text or email as the person picks (both offered when an email is on file) (the code is too long to type; deep links come later). An ended session (401 `unauthorized`) is refreshed once, shared by waiting requests; a failed refresh forgets the session and returns to sign-in; a wrong PIN is never retried. The app opens locked on later days: the PIN through `POST /auth/pin/login`, or fingerprint or face (offered after the PIN is set, and in Settings), which renews the stored session.
- API address: `EXPO_PUBLIC_API_URL` (the origin, without `/api`), else the Mac that serves the app on port 4000 (Expo Go knows its network address). The dev API listens on every interface (`HOST`, default `::`).
- Words: `src/i18n/en.ts` holds every string; Hausa, Yorùbá and Igbo files later with the same keys (missing keys fall back to English). Large text scales every text with the tokens' Large text sizes. Text is never below 16 points, body text 18; touch targets at least 48 points, big buttons 56.
- Theme: `src/theme/tokens.ts` is generated by `pnpm tokens` (`tools/tokens-to-mobile.mjs`) from `tools/penpot-ds-tokens.json`, the same catalogue as the web; screens use `src/theme/index.ts` names, never raw values.
- Capture (M3, `src/app/capture.tsx`): the app's camera only (`mode`: photo; milestone, two photos, the second "from another angle", sent as one claim; onsite, the RE's photo of a claimed milestone; incident, one photo handed back to M6 through `src/lib/handoff.ts`); the shutter waits for 25 m or better, or 60 seconds with `weak_location`; the photo carries the phone's time, position, accuracy, heading, mock flag, device id, lot and `phone_chainage_m`; six what-is-this tiles (discipline codes), an optional voice note (expo-audio, 60 s), shrunk to 2048 px JPEG 0.8 with a 400 px thumbnail.
- The outbox (`src/outbox/outbox.ts`, tests against a real SQLite file through node:sqlite): one SQLite row per item keyed by the phone's client id (the API is idempotent on it), files moved into the document folder on Send, sent one at a time when the app opens, when the network returns and every 30 s while open (`OutboxProvider.tsx`; Expo Go cannot upload in the background), waiting 30 s, 2 min, 10 min, then 30 min after failures; a refusal (a 4xx other than 408 and 429) waits for Retry; full-size files deleted once accepted, the thumbnail once verified; a warning after 24 h, too old after 72 h. Incidents go before everything else; a security incident is deleted from the phone (row and files) as soon as the API has it, and its place is never shown. A milestone claim carries a second photo (`photo2_path`, added to older tables on start). Items belong to the person who took them; signing out with unsent items warns and keeps them for that person only. M8 lists them with the five statuses, M7 shows what was sent back with Retake (`supersedes_id`).
- Status ladder on M2 (gap review): Queued (still on the phone, from the outbox), Sent (on the server, not yet decided), Verified, Sent back (not counting items already retaken on the server or on the phone), from `GET /field/my-submissions`; the lot and nearest chainage from `GET /field/context?lat=&lon=`; M9's queue from `GET /field/review-queue`.
- Mobile Step 3 (`src/app/report.tsx`, `milestones.tsx`, `incident.tsx`, `re-home.tsx`; manual checklist in `apps/mobile/MANUAL-TESTS.md`): M4 Today's report (workers with + and −, machines as a tick list with "Add a machine", the API's five weather values as tiles, any problem with an optional voice note; prefilled from this lot's last report on the phone or the server; one per lot per day, a resend the same day replaces it; through the outbox; the 16:00 reminder already counts it). M5 Milestones (by chainage with status; Open, Claimed on this phone, Claimed waiting for the RE, Verified; the last list kept for no signal; Mark complete opens the camera for two photos; the home card shows how many are open and the next). M6 Report incident (the four types as large tiles, a photo or a voice note or both; then "the resident engineer, the project manager and the security desk have been told", or saved and going first when there is signal). M9 (the queue one card at a time with the photo from a signed link, the chainage, the checks in plain words and Verify or Send back with a reason from the list, always at the bottom of the screen; Milestones to verify with Verify on site). Every "coming in the next step" screen is gone. Not built: the board's "Tests witnessed this week" card (no API yet) and swiping the card.
- Tests: `pnpm --filter mobile test` (jest-expo: the API client's refresh, sign-out on a failed refresh, no retry of a wrong PIN, the device id across restarts; the helpers) and `pnpm --filter mobile typecheck`, both in CI. `src/lib/storage.web.ts`, `src/outbox/device.web.ts` and `metro.config.js` (wasm for expo-sqlite on the web) let the web build run in a browser only to take screenshots at phone sizes and drive the screens with a fake camera and location (`apps/mobile/docs/screens/`, with the differences from the Penpot boards); it is never given to anyone. Metro there may serve stale code after edits: restart with `--clear`.

## Code conventions

- Repository: a pnpm workspace (`apps/*`, `packages/*`), Node 26 (`.nvmrc`). `apps/api` is the backend, `packages/shared` (`@fmot/shared`: roles, permissions) holds code shared by the API, web and mobile apps; it compiles to `dist`, and the API's build, start and test scripts build it first. Root scripts: `pnpm api` (API in watch mode), `pnpm web`, `pnpm dev` (both), `pnpm db:generate`, `pnpm db:migrate`, `pnpm db:seed`, `pnpm db:seed:demo` (demo branch only, docs/demo-data.md; it refuses main), `pnpm api:types` (OpenAPI document and shared types), `pnpm tokens` (web and mobile themes), `pnpm mobile` (the field app's dev server). The db scripts forward to the scripts of the same name in `apps/api`, which also has `db:studio`. pnpm only runs install scripts that `allowBuilds` in `pnpm-workspace.yaml` approves: esbuild is allowed, `@scarf/scarf` (install analytics) is denied. Approve new ones with `pnpm approve-builds <pkg>`.
- `packages/shared` also holds the workflow definitions (`workflows.ts`), so web and mobile can draw the chain.
- `apps/api` is an ES module package (`"type": "module"`, `nodenext`): relative imports end in `.js` (`import { DB } from '../database/database.module.js'`). Routes sit under `/api`; Swagger at `/api/docs`; `GET /api/health` checks the database and PostGIS. Config loads `apps/api/.env` (port, CORS) and the root `.env.local` (database URLs from `neon checkout`), validated by the zod schema in `src/config/env.ts`. The app uses the pooled `DATABASE_URL`; drizzle-kit uses `DATABASE_URL_UNPOOLED`. `pnpm test:e2e` runs against the checked-out Neon branch.
- API stack: Drizzle ORM with `pg` (drizzle-kit for migrations), `@nestjs/config` with zod for environment validation, class-validator and class-transformer for request DTOs, `@nestjs/swagger` for the OpenAPI document, helmet, and nestjs-pino logging (pino-pretty in development).
- Backend: NestJS 12 (TypeScript, strict), PostgreSQL with PostGIS on Neon, JWT with role-based access; scope is a row filter on every query, never trusted from the client. It replaced the earlier Java and Spring Boot plan on 2 November 2026 so the API, web and mobile apps share one language. Tests run on Vitest, linting on oxlint.
- Web: Next.js 16 with MapLibre GL (see Web app above).
- Errors: every error is `{ statusCode, code, message, details? }` from the global `ErrorFilter` (`src/common/errors.ts`). Throw Nest exceptions with `{ message, code }` for a specific code (`pin_incorrect`, `invite_expired`, `organisation_exists`); without one the code comes from the status (`not_found`, `not_allowed`, `conflict`, `too_many_requests`, ...), `validation_failed` for DTO errors, `internal_error` for anything unexpected (logged, message hidden). The web app's plain messages are keyed by these codes (`apps/web/src/lib/messages.ts`).
- The ValidationPipe (whitelist, transform) and the ErrorFilter are `APP_PIPE` and `APP_FILTER` providers in `AppModule`, so the e2e tests run them too. Every DTO property needs a class-validator decorator or the whitelist strips it.
- `HOST` (default `::`, every interface) is where the API listens, so a phone on the same network can reach the dev API; `127.0.0.1` keeps it on the machine.
- `TRUST_PROXY` (0 to 5, default 0) is the number of proxies in front of the API, used for `req.ip` (throttling, audit). Behind the web app's `/api` proxy and one load balancer it is 2.
- HTTP setup (`src/http.ts`, shared by `main.ts` and the e2e harness): body limits (JSON 256 kB, forms 64 kB; uploads have their own per-field limits in `receiveMultipart`), helmet, CORS, the `/api` prefix, trust proxy, and the OpenAPI document.
- `GET /api/ready` (readiness: 503 `not_ready` while shutting down or without the database) is separate from `GET /api/health`. On SIGTERM, `Lifecycle` (`src/common/lifecycle.ts`) marks the API not ready, stops background jobs from taking new work, gives the work in hand `SHUTDOWN_GRACE_MS` (default 20 s), and requeues what is unfinished. The pool closes last. Wrap new background jobs in `lifecycle.run()` and register their requeue with `lifecycle.onTimeout()`.
- `APP_ENV` (development, demo, test, staging, production) says where the API runs; demo is a machine showing the demo data, and only development and demo accept `DEV_SIGNIN_CODE`. `NODE_ENV=production` says how. The console SMS sender is allowed with `APP_ENV=staging`, never in production. `STORAGE_DRIVER` is `local` (`STORAGE_DIR`; staging uses a persistent volume) or `s3` (still a stub). Unset, it is local in development and s3 in production.
- OpenAPI: `pnpm api:types` builds the API, writes `packages/shared/openapi.json` (Nest preview mode, no database) and generates `packages/shared/src/api-types.ts` with openapi-typescript. Commit both; CI fails if they are stale. The document describes requests exactly but no responses yet (no response DTOs), so response shapes live in `apps/web/src/lib/api-shapes.ts`.
- Deployment: `apps/api/Dockerfile` and `apps/web/Dockerfile` (multi-stage, Node 26.11.1, run as `node`, build context the repository root, `.dockerignore` keeps env files out). The image migrates with `node dist/scripts/migrate.js` (drizzle-orm's migrator, same table as drizzle-kit; it refuses `main` without `ALLOW_MAIN_MIGRATIONS=1`). Staging is Fly.io, Frankfurt (`deploy/fly/*.staging.toml`, release command for migrations). CI is `.github/workflows/ci.yml`. Deploy, roll back, restore and secret rotation are in docs/operations.md.
- Directory routes for the web screens (`src/admin/directory.ts`): `GET`/`POST /api/admin/organisations`, `GET /api/admin/users?search=`, `GET /api/admin/projects`, `GET /api/admin/audit`, `GET /api/users?role=&search=` (the wizard's and W5.11's people picker), `GET /api/organisations?type=contractor|consultant` (the add-lot drawer: active ones, id and name only, `lots:manage`), `GET /api/reference/return-reasons`. Projects: `PUT /api/projects/:id` (basics while a draft), `DELETE /api/projects/:id/stations/:stationId`.
- Drizzle pitfall: in a single-table select, `${table.column}` inside a hand-written `sql` subquery renders unqualified (`"id"`) and binds to the subquery's own table. Use a joined query, `exists()` from the query builder, or write the column qualified (`"projects"."id"`).
- Mobile: Expo (React Native) in Expo Go, offline-first, in-app camera only; see Field app (mobile) above.
- British spelling in UI text and docs.
